> 拍照記錄三餐、估算熱量與營養素，依個人資料（身高 / 體重 / 體脂 / 活動量）算出

這是一個以「**好維護、可長期演進**」為原則的個人專案 / 作品集。

**目前定位**：自用與親友試用；食物辨識採**自建的開源模型**（不依賴付費 API）。
待功能夠深入、夠穩定後，再考慮商業化。

## 設計原則（為什麼這樣選）

1. **單一程式碼** — 用 Flutter 一套碼涵蓋 Android / iOS / Web，少一套要維護。
2. **本地優先（local-first）** — 資料存在手機本地，**沒有伺服器要顧**，維護負擔最低。
3. **辨識模組可抽換** — 最難的食物辨識藏在一個乾淨介面後面，將來要換實作不影響其他部分。

## 功能現況

- **今日**：熱量圓環（目標 / 已吃 / 剩餘）、三大營養素、記錄 / 編輯 / 刪除餐點（可復原、可從**最近吃過**與**台灣食物庫**快選）、依**餐別**（早 / 午 / 晚 / 點心）分組並顯示各餐小計、切換日期看歷史。
- **體重**：記錄體重 / 體脂，**可補記過去日期**，近 90 天趨勢折線圖，**目標體重**進度與預估達成時間（趨勢圖上有目標線）。
- **體組成**：記錄體脂計 / InBody 報告（脂肪量、骨骼肌、肌肉量、內臟脂肪、腰臀等圍度…，除了體重都選填），體重分頁顯示和上次比的變化：脂肪、腰圍下降標綠，骨骼肌下降標橘，**體重只標方向、不判好壞**（增肌減脂時體重不一定會降）；也算出 BMI 與腰臀比。
- **運動**：記錄有氧（時長、熱量、平均 / 最高心率、心率區間 Zone 1～5、感受）與肌力訓練（每台器材的重量 × 每組次數 × 組數，可一鍵**複製上次**）；時間照手錶的寫法輸入（31:49、1:00:53）。本週 / 上週的次數與總時間一眼看到；**器材清單**裡每台器材固定一種單位（kg / lb），點進去看歷次重量——不同器材的重量不互比，進步只跟同一台比。
- **統計**：分「飲食」與「增肌減脂」兩頁。
  - 飲食：近 7 / 30 天每日熱量長條圖（含目標虛線）、平均攝取、有記錄天數、達標天數、體重變化、**各餐別熱量分佈**（哪一餐吃最多）。
  - **增肌減脂**：選 4 週 / 12 週 / 全部，把同一段期間的體組成、訓練、飲食放在一起看——判讀「增肌減脂 / 減脂但肌肉也在減少 / 大致維持…」，把體重變化拆成「脂肪 ＋ 非脂肪」，畫出脂肪量與骨骼肌的走勢；訓練看每週頻率與各器材重量的變化，飲食看蛋白質每公斤體重幾克、各餐怎麼分配。
- **衛教**：分類文章，含破除迷思與飲食障礙識別 + 台灣求助專線；**每篇文末附資料來源**（衛福部 / 國民健康署、WHO、NICE 等官方指引，以及 JAMA、BJSM、Obesity 等同儕審查文獻），可點開原始出處自行查證。
- **健康建議**：填完資料後給客製化的「怎麼吃 / 動 / 睡 / 喝水」行動建議（也可隨時再看）+ 計算公式透明呈現。
- **備份**：一鍵**下載備份檔**（.json，檔名帶日期），換電腦或清除瀏覽器資料後選檔即可還原；還原前會先列出備份裡有幾筆資料，確認後才覆蓋（也還能用複製貼上文字）。另可下載**餐點 / 體重 CSV**，用 Excel、Google 試算表直接開啟，中文不會亂碼。
- **外觀**：以「新鮮蔬果」為概念的設計系統 —— 葉綠主色搭配柑橘 / 莓果 / 藍莓點綴，熱量與目標用漸層主卡 + 自繪圓環呈現，餐別（早 / 午 / 晚 / 點心）各有專屬顏色與圖示，BMI 有刻度尺看得出離健康區間多遠。深淺色模式跟隨系統；介面為繁體中文（含日期選擇器）；自訂 App 圖示與名稱「健康飲控」。

## 安全與責任設計

- **熱量下限**：每日目標設有安全下限（女 1200 / 男 1500 大卡），不鼓勵極端節食。
- **目標體重**：低於身高對應的健康體重區間時會明確提醒並建議調整，不協助追求過低的體重。
- **預估時間誠實標示**：達成時間以線性公式估算，畫面上直接說明實際通常更慢。
- **體組成看趨勢**：家用體脂計（BIA）會受水分、飲食、生理期影響，畫面直接提醒在相近條件下量、看多次趨勢，不要只看一次的升降。
- **分析不硬下結論**：增肌減脂分析把 0.5 公斤以內的變化當作「看不出來」，只有兩次量測時標明「先當參考」；訓練與飲食從第一筆紀錄起算，不會把還沒開始記錄的日子算成沒運動、沒吃；蛋白質與肌力訓練的建議值附上出處（統合分析、WHO 指引）。
- **估算非精準**：拍照熱量為估算值，份量由使用者調整，僅供方向性參考。
- **非醫療建議**：本 App 不取代專業醫療或營養師診斷；衛教內含求助資源。
- **內容可查證**：衛教文章一律附資料來源，並標明「這個來源支持文中哪個說法」；有爭議或證據未定的說法（如局部瘦身、7700 大卡換算）在文中直接說明侷限，不寫成定論。
- **限制對外連線**：正式版用內容安全政策（CSP）只准 App 連到本站與 Google 的繪圖引擎、字型；就算哪個套件被植入惡意程式，也無法把紀錄偷傳到別的網站 → [資安說明](docs/SECURITY.md)
- **建置環境鎖版本**：CI 與部署固定 Flutter 版本、第三方建置工具鎖在固定的 commit；部署出去的就是本機測過的版本，建置工具也不會被悄悄換掉 → [部署說明](docs/DEPLOYMENT.md)

## 開發指令

```powershell
flutter test                                          # 跑單元 / Widget / 資料庫整合測試
flutter run -d chrome --web-port=8081                 # 在 Chrome 預覽（含熱重載）
flutter analyze                                       # 靜態檢查
dart run build_runner build                           # 改 drift schema 後重新產生程式碼（流程見 docs/DATABASE.md）
dart run drift_dev schema dump lib/data/database.dart drift_schemas/   # 改完 schema 留一份快照
dart run tool/generate_icon.dart                      # 重新產生各平台 App 圖示
flutter build web --release --csp                     # 建置正式版 Web（--csp 配合對外連線白名單）
dart run tool/enable_csp.dart                         # 啟用白名單（只在正式版；見 docs/SECURITY.md）
```

> **Web 須知**：drift 在 Web 需要 `web/sqlite3.wasm` 與 `web/drift_worker.js`
> 兩個靜態資源（已隨專案附上，版本對應 drift 2.34 / sqlite3 3.3.3）。
